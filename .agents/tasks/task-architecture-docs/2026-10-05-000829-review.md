# Architecture diagram + bilingual README split (v1)

Issue #23 adds an editable AWS architecture diagram in three mutually-consistent forms (`docs/architecture.drawio` as the draw.io source, `docs/architecture.svg` as a hand-authored vector, `docs/architecture.png` as the README raster) plus the raw `docs/aws-icons/*.svg`, and splits the single bilingual README into an English-baseline `README.md` and a Japanese `README.ja.md`, each led by a language switcher and carrying an `## Architecture` section that embeds the PNG and links the editable sources. The change is docs-only — nothing under `packages/` or `infra/` is touched, and `npm run build` / `npm run test` (47/47) stay green as a sanity gate. The diagram faithfully encodes the real topology: Browser → CloudFront → private S3 via OAC, Browser → API Gateway v2 → four Lambdas → one DynamoDB table, with a single Bedrock edge originating only from the `chat` Lambda. The split preserves every substantive section and the exact switcher strings.

Watch for: one newly-introduced broken intra-page anchor in `README.md` — the Prerequisites link to the overriding-model-IDs section still targets the old bilingual slug after the heading was changed to English-only (confirmed). The JA file's equivalent link is correct.

**Verdict**: NEEDS_CHANGES

## High-level view

The diagram set is the heart of this change and it holds up: all three representations depict the same graph, and the one architectural detail that is easy to get wrong — that only `chat` reaches Bedrock while the other three Lambdas do not — is drawn correctly and reinforced with a stage-tier note. The private-S3-behind-CloudFront-via-OAC relationship, the four labeled routes, and the per-Lambda DynamoDB access modes all match the CDK stack. No per-deploy URLs are baked in.

The README split is faithful. The switcher strings are exact and sit as the first content line under the title in both files, the old ASCII architecture block is gone, section parity is intact (ten top-level sections each, SUBMISSION.md link preserved in both), the product name stays "AIモンスター / AI Monster", and no "Digital Monster" product name is reintroduced (the retained `DigitalMonsterStack-Monsters` table name and `digital-monster-stack.ts` path are infra identifiers, correctly left as-is).

The one defect is a broken anchor introduced by the heading rewrite. When the overriding-model-IDs heading was de-bilingualized in `README.md`, its GitHub slug changed, but the Prerequisites cross-reference that points at it was not updated, so the link now dead-ends. This is isolated to the English file.

The old single README used the heading `## 🔧 Bedrock モデルIDの上書き / Overriding model IDs` and a Prerequisites link to `#-bedrock-モデルidの上書き--overriding-model-ids`; those matched. ### Diagram fidelity evidence (chat-only Bedrock, private S3 via OAC)

The chat-only Bedrock claim is encoded identically in all three sources: the drawio has one edge `source="lchat" target="bedrock"` labeled `bedrock:InvokeModel` and none from `lgetMonster`/`lsaveMonster`/`lbattle`; the SVG has one teal polyline from the chat row to the Bedrock icon; the PNG shows that teal arrow leaving `chat` only. The other three Lambdas connect only to DynamoDB with the access modes the stack's IAM grants imply — `getMonster` R/W, `saveMonster` W, `battle` R/W, `chat` read. The CloudFront → S3 edge is labeled `OAC (SigV4) · serves static` with S3 marked "Block Public Access ALL", and the browser's config.json/API path is a separate edge, so static-vs-API traffic is not conflated. us-east-1 sits on the AWS Cloud boundary and no per-deploy hostnames appear, honoring the don't-hardcode-URLs constraint. The four routes (`GET /monster/{monsterId}`, `POST /monster`, `POST /battle`, `POST /chat`), the table identity (`DigitalMonsterStack-Monsters`, PK = id, PAY_PER_REQUEST), and the stage-tier note (baby = canned reply, rookie/champion/ultimate = Haiku/Sonnet/Opus) all agree across sources and with `bedrock-models.ts`. The drawio uses real `mxgraph.aws4.resourceIcon` shapes (editable), the SVG inlines official AWS icon paths, the PNG is a 1180×720 raster of the SVG, and all eight XML files parse well-formed.
