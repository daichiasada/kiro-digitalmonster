# JA/EN language toggle and i18n layer for the monster game (v1)

Adds a Japanese/English UI toggle plus end-to-end localization: a dependency-free in-house i18n layer (`i18n.ts`), language-aware pure helpers (`ui-helpers.ts`), English stage labels in `@ddm/shared`, a header JA/EN toggle persisted to `localStorage`, and an optional `lang` field on the chat DTO so the Bedrock prompt and canned replies follow the selected language. The design keeps Japanese output byte-identical to the pre-change behavior whenever `lang==='ja'` (the default), and the backend treats a missing `lang` as `ja`, so already-deployed clients are unaffected. The approach is a message-key dictionary with compile-time key parity between JA and EN, a pure `t(lang, key)` lookup with graceful fallback, and a React context layer written with `createElement` so the module stays importable by the Node test runner.

Watch for: one *confirmed* JA-output difference — `chat.disabledHint` carries a leading space that the original JSX rendering did not have (cosmetic, HTML collapses it, non-blocking). Monster sprite `title` tooltips remain hard-coded Japanese in both languages (*confirmed*, but pre-existing and out of scope). Error-path toast strings and the chat-failure fallback stay Japanese (*confirmed*, acknowledged as acceptable).

**Verdict**: APPROVED

## High-level view

The localization strategy is a single source-of-truth JA dictionary from which the message-key type is derived; the EN dictionary is typed `Record<MessageKey, string>` so a missing or extra key fails compilation. That gives real key-parity enforcement rather than a runtime check only. `t()` degrades through JA and then the raw key, so a missing translation never throws or renders `undefined`.

The React layer is deliberately isolated at the bottom of `i18n.ts` and uses `createElement`, and all `localStorage` access is lazy and guarded. This is what lets the frontend unit suite import the module under `node --test` without a DOM. Persistence is `ddm.lang`, default `ja`, read once on mount and written on every change.

JA preservation is handled by routing every component string through either `t(lang, key)` or a language-aware helper whose `ja` branch delegates to the original `*Ja` function, with wrapper tests asserting byte-identity for `lang==='ja'`. The one leak is the leading space in `chat.disabledHint`.

The backend change is minimal and backward-compatible: `lang` is optional, anything other than an explicit `"en"` collapses to `"ja"`, and the Japanese prompt / canned reply / empty-reply fallback are returned unchanged on that path. The English prompt is a parallel six-line block that instructs the model to answer in English.

Translation coverage spans the strings introduced by the recent feature work (evolution-conditions panel, battle animation log and result headline, care-animation buttons, chat speech bubble empty/baby states). The battle log is re-localized live when the toggle flips because `lang` is folded into the animation's replay identity. The remaining untranslated surfaces are the sprite `<title>` tooltips (pre-existing) and error toasts (acknowledged).

### JA byte-identity: the one divergence

The divergence is in the dictionary, not the helpers. `chat.disabledHint` is `" 幼年期のあいだはまだ言葉を話せません。…"` with a leading space. In the base branch the text sat on its own line inside `<p>…</p>`, and JSX strips whitespace adjacent to newlines, so the rendered node had no leading space; `{t("chat.disabledHint")}` now emits the literal with the space included. HTML collapses a single leading space in block flow, so there is no visible difference, but it breaks the strict byte-identical JA claim for this string. `care.hint` and `app.footer`, which had the same on-its-own-line origin, were transcribed without a leading space and are exact — only `disabledHint` differs.

### Backend lang handling

`const lang: Lang = body.lang === "en" ? "en" : "ja"` is fail-safe toward the legacy path: any absent, malformed, or unexpected value yields `ja`, so an old client that never sends `lang` gets the original behavior. The English variants are added as parallel branches rather than by rewriting the Japanese ones, which is why the JA bytes are preserved. The baby and empty-reply English strings match the frontend's `BABY_SPEECH_TEXT_EN` so a baby-stage bubble and a real backend baby reply read identically.

### Live re-localization of the battle log

`BattlePanel` folds `lang` into the animation's replay identity (`id = ${lang}\n${log.join("\n")}`) and into the effect dependency array, so toggling language mid-battle restarts playback and rebuilds the revealed lines through `battleLogLine(..., lang)` instead of leaving stale JA lines on screen. Without this, a flipped toggle would leave the already-revealed log untranslated. The enemy name is rebuilt from the `battle.enemyName` template (`野生の{label}モンスター` → `野生の幼年期モンスター`), reproducing the original interpolation exactly for JA.

### Test coverage gaps

The 16 added assertions pin exact EN strings, assert `lang==='ja'` equivalence against the legacy helpers, verify dictionary key-set equality, and exercise both fallback legs of `t()` (missing-in-one-language and missing-in-both). Not tested: the exact rendered value of `chat.disabledHint` (so the leading-space issue isn't caught), and the React provider / `localStorage` persistence path — the toggle→persist→reload loop is only validated manually.
