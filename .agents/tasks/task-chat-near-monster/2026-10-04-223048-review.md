# Chat UI moved next to the monster sprite

The conversation panel (input, send button, transcript, and the baby-stage disabled hint) was relocated in `App.tsx` from the right-hand `controls-area` column into the left-hand `stage-area`, dropped in directly after the sprite wrapper and before `StatsPanel`. This puts the full chat UI in the same column as the sprite and the existing `#11` speech bubble, so a conversation now reads as self-contained around the monster instead of being split across two columns. `ChatPanel`'s props are unchanged, the component and `i18n.ts` were not touched, and the only CSS change tightens `.chat-log` max-height from 220px to 180px to keep the now-taller left column from towering over the controls column in the two-column layout.

**Watch for:** the left column (`stage-area`) now stacks sprite + chat + stats while the right column keeps care + battle, which shifts the two-column height balance — a layout-only effect that could not be visually verified in this sandbox (confirmed the imbalance exists by reasoning; possible that it reads awkwardly in practice). No functional, i18n, or responsive-rule changes.

**Verdict**: APPROVED

## High-level view

The move is a pure JSX relocation: the `<ChatPanel>` element is lifted verbatim out of `controls-area` and reinserted into `stage-area` between `sprite-wrap` and `StatsPanel`, with props byte-identical. Behavior of the panel — baby-stage disabled hint, pending `…` indicator, send gating — is carried by `ChatPanel.tsx`, which was not modified, so none of that UX changes.

Responsiveness is governed entirely by the untouched `.game-grid` rules (single column below 760px, `1fr 1fr` at/above 760px). Moving a child between the two grid columns doesn't alter those rules, so the collapse behavior is preserved; what changes is the relative height of the two columns, since the left column now carries three stacked panels and the right carries two. The `.chat-log` max-height reduction (220px → 180px) is the author's deliberate mitigation for that imbalance, documented in a CSS comment.

The known gap is verification: a live render wasn't possible here, so the visual outcome of the new column balance and the stacked left-column ordering (sprite → chat → stats) rests on CSS reasoning rather than a screenshot.

### Column composition and the height-balance trade-off

Within `stage-area` (a `display: grid; gap: 16px` column) the vertical order is now sprite-wrap → ChatPanel → StatsPanel; on `main` it was sprite-wrap → StatsPanel. The chat sits between the sprite and the stats, directly under the `#11` `SpeechBubble` that is absolutely positioned inside `sprite-wrap`, which is what makes the conversation "complete" visually near the monster — the stated goal.

```
<760px (single column)          >=760px (two columns)
┌─────────────────┐             ┌──────────────┬──────────────┐
│ sprite + bubble │             │ sprite+bubble│ care         │
│ chat panel      │             │ chat panel   │ battle       │
│ stats           │             │ stats        │              │
│ care            │             └──────────────┴──────────────┘
│ battle          │              left: 3 panels  right: 2 panels
└─────────────────┘
```

The cost is the two-column height asymmetry: the left column grows by a full panel's worth of height relative to the right. The author anticipated this and reduced `.chat-log` max-height to 180px with an explanatory comment, which caps transcript growth but does not change the baseline that the left column is now the taller of the two. This is a layout-aesthetics concern, not a correctness one; it could not be render-verified in this sandbox (live Playwright can't reach host localhost and the deployed URL still serves pre-change `main`), so the assessment rests on CSS reasoning. Worth a screenshot at ≥760px before shipping, but not blocking.

### Scope and responsive guarantee

The `.game-grid` rules were not modified and `align-items: start` already governs column alignment, so the <760px collapse and the ≥760px split behave as before — the only responsive-adjacent effect is the per-column height above. The change is otherwise confined to chat placement: two files, no new props, no new runtime dependencies, no backend or shared-package touch.
