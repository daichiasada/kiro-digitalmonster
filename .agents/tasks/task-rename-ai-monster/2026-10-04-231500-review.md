# Rename product name "Digital Monster" → "AI Monster" across display strings (v2)

The change swaps the product's human-readable name from "Digital Monster / デジタルモンスター" to "AI Monster / AIモンスター" wherever it appears as prose or a display string — frontend i18n and page title, monster sprite tooltips, backend chat system prompts, doc comments, package descriptions, README title, `.kiro` spec/power prose, and both `.env.example` comment headers. Every structural identifier is deliberately left alone: the CDK stack ID and class, npm `@ddm/*` scopes, the root `kiro-digitalmonster` package name, and all `digital-monster` filesystem paths. The diff is now 21 files (19 in v1 plus the two `.env.example` fixes added this pass), each a one-line text swap with no logic touched.

Watch for: nothing blocking. The sole v1 issue — a residual "Digital Monster" comment in `packages/frontend/.env.example` — is fixed (confirmed), and the broadened audit caught and fixed a second extensionless file, root `.env.example` (confirmed).

**Verdict**: APPROVED

### v1 issue resolved, plus a second extensionless miss caught

The v1 review flagged `packages/frontend/.env.example` line 1 as the one tracked file still carrying the old name, caused by the completion grep filtering on `*.ts/*.tsx/*.json/*.md/*.html` extensions. Commit `93ec168` fixes it:

```
-# Build-time API base URL for the Digital Monster backend (API Gateway invoke URL).
+# Build-time API base URL for the AI Monster backend (API Gateway invoke URL).
```

The same commit broadened the audit to all tracked files rather than an extension list, which is what surfaced a second file the original grep could never have caught — root `.env.example`:

```
-# Digital Monster - example environment variables
+# AI Monster - example environment variables
```

Both files read "AI Monster" on the branch tip. The fix addresses the root cause (extension-scoped audit) rather than just the one reported symptom.

### No surviving display strings; only preserved identifiers remain

A case-insensitive sweep for `digital[ -]*monster` and `デジタルモンスター` across tracked files (excluding `node_modules`, `dist`, `cdk.out`, `package-lock.json`, `.agents/`) returns only identifier and path references, each intentionally preserved:

- `infra/bin/app.ts` — the import and `new DigitalMonsterStack(app, "DigitalMonsterStack", …)` call; renaming either would change the synthesized stack name and orphan the live stack.
- `infra/lib/digital-monster-stack.ts` — `DigitalMonsterStackProps`, the `DigitalMonsterStack` class, and the file-path comment.
- `package.json` — the root `kiro-digitalmonster` package name.
- `.kiro/specs/digital-monster/*`, `.kiro/steering/structure.md`, `.kiro/hooks/*`, `.kiro/powers/digimon-helper/*`, `README.md`, `SUBMISSION.md` — references to the `digital-monster` spec/path and the `kiro-digitalmonster` repo token, all paths or identifiers, not the product name.
- `SUBMISSION.md` — "デジモン風" is a genre descriptor ("Digimon-style"), not the product name.

The katakana product name デジタルモンスター has no matches anywhere in scope, confirming the Japanese display rename is complete.

### Infra, i18n, prompts, and the pinning test unchanged from v1

The CDK stack ID literal, class, interface, and import path are still present and unchanged, so the synthesized stack name and logical IDs are identical. Both `app.title` values carry the new name (JA `AIモンスター育成`, EN `AI Monster Raising`), and the two `game-ui.test.ts` assertions still check those exact literals, so a reverted rename fails the suite. The backend `chat.ts` prompts carry `You are an AI monster named "${context.name}".` and `あなたは「${context.name}」という名前のAIモンスターです。`, with the name interpolation intact.
