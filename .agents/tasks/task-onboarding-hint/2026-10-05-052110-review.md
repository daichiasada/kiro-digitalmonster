# First-run onboarding hint with evolve call-to-action (v1)

Adds a lightweight, dismissible first-run hint that tells a brand-new player what to do first ("start Training to reach the Rookie stage"). The hint renders at the top of the stage area only on a fresh profile and only once a monster has loaded; dismissing it persists a `ddm.onboarded` flag in localStorage so it never reappears. The implementation deliberately mirrors the existing `EvolutionBanner` (a `role="status"` inline strip with a close button, not a modal), keeps all decision logic in pure, unit-tested helpers, and derives its call-to-action from the shared `evolutionProgress` snapshot so the displayed "remaining" numbers can't contradict the real AND-gate evolution rule. JA/EN strings are added to both dictionaries, and the EN dict's `Record<MessageKey, string>` typing forces parity at compile time.

Watch for: the hint re-shows on a *returning* profile whose flag isn't set yet even if the monster is already past baby — the CTA adapts correctly, so this is a behavior note, not a bug (confirmed). The CTA line always renders including a "fully grown" variant that a true first-run player can never actually hit (possible dead branch, cosmetic).

**Verdict**: APPROVED

## High-level view

The gating logic is split cleanly: `readOnboarded`/`writeOnboarded` touch localStorage behind a `typeof` guard and try/catch and default to "show" when storage is unavailable, while the actual show/hide decision is the pure `shouldShowOnboarding(onboarded, hasMonster)` so it can be tested without a DOM. `App` reads the flag once via a lazy `useState` initializer and flips it on dismiss; the hint is only mounted while `game.monster !== null`.

The call-to-action is `onboardingCta(prog, lang)`, a pure function over the shared `EvolutionProgress`. It clamps remaining training and remaining time to `>= 0`, reuses `formatMinutes` for the minute wording, and reads from i18n templates. Because it consumes the same snapshot that encodes `evolveStage`'s AND-gate, the "2 more training, 1 min" summary stays truthful to the real evolution requirement.

The five new strings land in both JA and EN dictionaries with the EN side typed as `Record<MessageKey, string>`, so a missing translation is a build error rather than a runtime fallback. No runtime dependencies were added, and the entrance animation is turned off under `prefers-reduced-motion: reduce`.

Test coverage exercises the two pure helpers directly — a `shouldShowOnboarding` truth table and `onboardingCta` across fresh-baby (exact JA+EN strings), over-satisfied clamping, and final-stage. The React component, the storage guards, and the `App` wiring are not covered by automated tests.

### Storage gating never throws and defaults to "show"

`readOnboarded` guards on `typeof localStorage === "undefined"` and wraps the access in try/catch, returning `false` (show the hint) when storage is absent or blocked. The truthiness check is deliberately strict — `stored !== null && stored !== "" && stored !== "0"` — so an empty string or a legacy `"0"` value both read as "not onboarded." That is more defensive than a bare `stored !== null` and correctly pairs with `writeOnboarded` writing `"1"`. `writeOnboarded` swallows quota/private-mode failures, which means a dismiss can silently fail to persist; the UX consequence is only that the hint returns on the next load in a locked-down browser, which is the right fail-open-for-visibility trade-off for an onboarding nudge (confirmed).

The flag is read once through a lazy `useState(readOnboarded)` initializer, so a dismiss in one tab won't retract the hint in another already-open tab. For a one-time onboarding nudge this is immaterial (confirmed).

### CTA derivation stays consistent with the shared AND-gate

`onboardingCta` reads `trainingRequired`/`trainingCurrent` and `requiredMs`/`elapsedMs` off the shared snapshot and clamps each remainder with `Math.max(0, ...)`:

```ts
const remainingTraining = Math.max(0, (prog.trainingRequired ?? 0) - prog.trainingCurrent);
const remainingMs = Math.max(0, (prog.requiredMs ?? 0) - prog.elapsedMs);
```

Because evolution requires training **and** age independently, surfacing both remainders separately ("0回・1分") is the honest summary — a player who finished training still sees the minutes they must wait, matching `evolveStage`. `formatMinutes` already carries its own unit ("分" / " min"), so the template places `{minutes}` without appending one; the exact-string tests ("…・1分", "…1 min") pin that down. One behavior note: the `onboarding.ctaFinal` branch (via `prog.isFinalStage`) can only render for a monster already at the ultimate stage, which a genuine first-run player never is — correct and tested, but effectively dead for the onboarding audience (possible).

### Dismiss affordance differs from the banner

`OnboardingHint` mirrors `EvolutionBanner`'s structure, with one deliberate divergence: the banner dismisses on a click anywhere on its surface, whereas the hint dismisses only via the × button. That's the right call here — an onboarding hint shouldn't vanish on an accidental stage-area click (confirmed). The understated translucent strip reuses the existing `--text`/`--muted` tokens and `.onboarding-close` mirrors `.evo-close`, so the tone stays with the restrained palette rather than a modal overlay, and the `hint-fade-in` entrance is disabled under `prefers-reduced-motion: reduce`.

### Test coverage

Four new tests target the pure helpers: a `shouldShowOnboarding` truth table over all four input combinations, and `onboardingCta` across a fresh baby (asserting exact JA and EN strings, which pins both interpolation and label wiring), an over-satisfied monster (asserting the `>= 0` clamp yields "0回・0分" / "0 min"), and the final stage. These pin the behavioral contract of the logic that actually decides visibility and wording.

Not tested: the `readOnboarded`/`writeOnboarded` storage guards (the undefined-storage and throw paths), the `OnboardingHint` component rendering, and the `App` lazy-init/dismiss wiring. The storage fallbacks are the only untested branches with real failure semantics; a small test stubbing a throwing `localStorage` would close that gap. Full suite is green (59 frontend helper tests, up from 55; root `npm test` baseline unchanged) and the frontend build (tsc + vite) passes clean.
