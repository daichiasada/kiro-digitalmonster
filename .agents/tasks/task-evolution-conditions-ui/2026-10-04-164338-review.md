# Evolution-condition visibility in the StatsPanel (v1 review)

Adds a 進化条件 block to the stats panel so a player can see what the next evolution needs and how close they are. The behavioral core is a new pure function `evolutionProgress(monster, now)` in `@ddm/shared` that deliberately mirrors the AND-gate used by `evolveStage` (trainingCount ≥ minTrainingCount **and** elapsed ≥ minAgeMs), so what the UI shows can't drift from what actually triggers evolution. A frontend `formatMinutesJa` helper renders durations as whole-minute Japanese strings, and `StatsPanel` draws next-stage label, `トレーニング N/M`, `経過 X分/Y分`, per-condition ✓/・ indicators, and a `最終段階（完全体）` line at the terminal stage. All strings are Japanese-only, no new runtime deps.

Watch for: progress is computed from `Date.now()` only at render time, so the elapsed/age line is stale until the next re-render (likely); the final-stage label is sourced from the frontend's duplicated label map while the next-stage label comes from shared (confirmed, values currently agree).

**Verdict**: APPROVED

## High-level view

`evolutionProgress` recomputes the same two gates `evolveStage` uses rather than inventing a parallel notion of "ready", and a test asserts the met-flags agree with `evolveStage` actually advancing. This coupling is why the display can't drift from the real evolution logic.

The terminal stage is handled by `evolveRequirement === null`, not by matching the `ultimate` id, and the component branches on `isFinalStage`, so adding stages later won't silently break the final-stage message.

The one behavioral caveat is freshness: elapsed minutes are frozen at render time, so the age line can sit stale while the monster is already eligible unless something re-renders the panel on a tick. Worth confirming against how the app drives updates.

<summary>Details</summary>

### Progress mirrors the real evolution gate

`evolutionProgress` computes `trainingMet`/`ageMet` from the same `evolveRequirement` thresholds and the same `elapsed = now - bornAt` comparison `evolveStage` uses. The test `evolutionProgress met-flags agree with evolveStage advancing` drives a monster to the exact threshold and asserts both that the flags flip true and that `evolveStage` returns `rookie` for the same `(monster, now)` — the guard against the display claiming "ready" when the engine disagrees, or vice versa.

`elapsedMs` is clamped to `>= 0`: `now` is passed in, so clock skew or a future `bornAt` would otherwise surface a negative "経過". Covered by a dedicated test.

### Terminal stage handling

One asymmetry at the final stage: the line renders `最終段階（{stageLabelJa(monster.stageId)}）` using the frontend's local `STAGE_LABELS_JA` map, while every other label in this feature flows from the shared config via `prog.nextLabelJa` / `currentLabelJa`. The two maps carry identical strings today ("完全体"), so there's no visible bug, but it's two sources of truth for the same label. Using `prog.currentLabelJa` here would keep the whole block on the shared config.

### Render-time snapshot of elapsed time

`StatsPanel` computes `const now = Date.now()` in the render body. The `トレーニング N/M` line tracks the monster object and stays accurate, but the `経過 X分/Y分` line reflects wall-clock only as of the last render and does not advance on its own. If the panel only re-renders on explicit user actions, the elapsed line and its ✓ lag the real elapsed time, showing the age condition as unmet after it has actually been satisfied — the one place the display can transiently contradict `evolveStage`. Check how `StatsPanel` is driven before relying on the age indicator.

### formatMinutesJa and the Japanese-only constraint

`formatMinutesJa` floors to whole minutes and guards non-finite/negative input to `"0分"`, so the `経過` line can't render `NaN分` or a negative. Flooring (not rounding) suits a "progress toward a threshold" readout — it won't show `5分/5分` until the threshold is genuinely crossed. Every introduced string (進化条件, 次の段階, トレーニング, 経過, 最終段階, 分) is Japanese and the ✓/・ markers are glyphs, so the issue #8 Japanese-only constraint holds and no i18n scaffolding leaked in from #12.

### Test coverage

Shared tests cover the fresh-baby requirement, partial progress against the issue's own example shape (`3/6`, `2分/5分`), the met-flags-agree-with-evolveStage coupling, the terminal stage null/true encoding, and the negative-elapsed clamp — the behaviorally meaningful cases, not just getters. The frontend test exercises `formatMinutesJa` at 0, exact-minute, floor, negative, and NaN.

Not tested: `StatsPanel` rendering itself — there's no assertion that the final-stage branch renders `最終段階` or that the met/unmet className actually tracks `trainingMet`/`ageMet`. Given the component is thin and the logic lives in tested helpers this is a low-value gap, but the ✓-vs-・ and `.met`/`.unmet` wiring is untested glue. The render-time staleness above is also not exercised (and arguably can't be at the unit level).
