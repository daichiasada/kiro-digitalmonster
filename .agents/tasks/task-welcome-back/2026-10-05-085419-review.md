# Welcome-back absence summary (おかえり画面) — issue #40 (v1)

A returning player now gets a "while you were away" strip summarizing what changed during their absence (hunger, dirt, HP loss from starving, HP recovery while sleeping, evolution) plus a one-tap recommended-care button. The diff is a pure `summarizeAbsence(before, after)` in `@ddm/shared`, computed once at mount from the loaded monster vs the `applyTimePassage`-advanced monster, and only when the real absence (`now - lastUpdatedAt`) crosses a 5-minute threshold. The panel is a `role="status"` strip (not a modal), dismissible by keyboard, and dismissal is session-scoped because the summary is only ever recomputed in the mount effect — the 15s tick never touches it. All acceptance criteria are met and both test suites pass (shared 140, frontend 112).

**Watch for:** `recommendedCareAction` (the summary-based recommender) is exported but never used and never tested — dead surface (confirmed). The one-tap action is gated by the hook's `busy` flag, so a tap during an in-flight save dismisses the panel without applying the care (possible). The displayed recommendation re-derives from the live monster every render, so a background tick could shift the label while the panel is open (likely, low impact).

**Verdict**: APPROVED

## High-level view

The behavioral core is a single pure function. `summarizeAbsence` diffs two monster snapshots, derives `elapsedMs` from the two `lastUpdatedAt` values so it stays a pure two-arg function, and separates HP movement into starving-loss vs sleeping-gain using the pre-advance `isSleeping` flag.

Threshold gating and the double-count guard live in `useMonster`'s mount effect. The summary is set exactly once, from `now - loaded.lastUpdatedAt >= ABSENCE_SUMMARY_THRESHOLD_MS`, skipping freshly hatched monsters. The 15s `TIME_TICK` interval deliberately never sets `welcomeBack`, which is what makes session-scoped dismissal correct: once `dismissWelcomeBack` nulls it, nothing re-opens it until the next mount.

The recommendation uses `recommendCareFromMonster(after)` (absolute post-advance state: feed > clean > wake > none); both the button label and the executed action derive from that same call, so they can't disagree. A parallel summary-based `recommendedCareAction` exists but is unused and untested.

i18n adds twelve `welcome.*` keys to both JA and EN with no changes to existing keys, and the frontend pure helpers (`formatDuration`/`formatDurationJa`/`recommendLabelKey`) carry the display logic and are tested. The known gap is that the stateful glue — mount gating, dismissal, the tick guard — has no automated test, consistent with the project's no-DOM/no-React test convention.

## Pure diff core and the before/after contract

Deriving `elapsedMs` from `after.lastUpdatedAt - before.lastUpdatedAt` (rather than a separate `now`) means that — because `applyTimePassage` sets `lastUpdatedAt = now` — the displayed elapsed time is exactly the real absence used for gating, so the two can never disagree. HP movement is attributed by direction and the pre-advance sleep flag: `hpLostFromStarving` only when awake, `hpGainedFromSleeping` only when `before.isSleeping`, matching `applyTimePassage` (awake loses HP only at max hunger; sleeping recovers `ticks * 2`). `affectionOf`/`formOf` normalize legacy saves so the diff is stable on pre-#38/#42 records.

The test file exercises the meaningful branches: zero-gap and sub-tick no-change, hunger-only, the 3-tick dirty boundary, starving HP loss (asserting `hpLostFromStarving === -hpDelta` and `hpGainedFromSleeping === 0`), sleeping HP gain with no hunger/affection movement, evolution with from/to stage and form assertions, a combined gap, and a no-mutation check via JSON snapshots. These assert the attribution logic, not just that a number changed.

## Threshold gating and the TIME_TICK double-count guard

```
mount effect:
  loaded  = getMonster()            // pre-advance, carries last-visit lastUpdatedAt
  advanced = advance(loaded, now)   // applyTimePassage + normalizers
  absenceMs = max(0, now - loaded.lastUpdatedAt)
  if !hatchedFresh && absenceMs >= THRESHOLD:
      setWelcomeBack(summarizeAbsence(loaded, advanced))   // ONLY writer

15s interval: advances the monster, commits on change — never writes welcomeBack
```

The fresh-hatch path is excluded (a new egg has no absence), and the summary is set from the real last-visit gap. Because the interval never writes `welcomeBack`, a later tick cannot re-open a dismissed panel — exactly what "閉じるとその回は再表示しない" requires: dismissal nulls the state and only a fresh mount can repopulate it.

The summary text is captured as a stable snapshot, but `recommendCareFromMonster(game.monster)` in `App` is recomputed on every render from the live, still-ticking monster. A background tick (e.g. hunger crossing the caution level) can therefore change the button label after the summary was captured — low impact over the short window the panel is open, but the label is not frozen with the summary.

## One-tap recommendation wiring

Label and action both come from the same `recommendCareFromMonster(game.monster)` call, so they cannot disagree: the label is `recommendLabelKey(rec)` and the handler switches on the same `rec`, mapping `feed`/`clean` to the care actions and `wake` to the `sleep()` toggle (which wakes when asleep). `none` hides the button and the handler only dismisses.

The handler runs `void game.feed()/clean()/sleep()` and then unconditionally calls `dismissWelcomeBack()`. Those care actions early-return when the hook's `busy` flag is set, so a tap that lands during an in-flight save applies nothing yet still closes the panel — the player's one intended action is silently dropped. Dismissing after the action resolves, or exempting this path from the `busy` guard, would close the gap.

`recommendedCareAction(summary)` is the summary-based twin of the monster-based recommender, with a deliberately different first rule (`hungerDelta > 0` rather than absolute hunger level). Nothing imports it and no test covers it, so its distinct behavior is unverified. It should be wired, tested, or removed.

## Accessibility and i18n

The panel is a `role="status"` strip with a focusable close button and no focus trap, matching the existing `OnboardingHint` pattern; each change line pairs text with an `aria-hidden` emoji so cues are not color-only, and the entrance animation is behind `prefers-reduced-motion: no-preference`. Twelve `welcome.*` keys are added to both JA and EN with existing keys untouched; `EN_MESSAGES` is typed `Record<MessageKey, string>`, so a missing key would fail the build, and the test "recommendLabelKey results resolve to real messages in both languages" asserts the three button keys resolve in both dictionaries.

## Test coverage

Covered: the full `summarizeAbsence` attribution matrix, `recommendCareFromMonster`'s four-way priority, `formatDuration`/`formatDurationJa` (rounding, hour-omission below 60m, non-finite/negative guards, ja/en parity), and `recommendLabelKey` mapping plus both-language resolution.

Not tested: the mount-only gating, the TIME_TICK double-count guard, and session-scoped dismissal — the acceptance-critical stateful behaviors — have no automated coverage, since the project tests only pure helpers (no DOM/React). `recommendedCareAction` is also untested.
