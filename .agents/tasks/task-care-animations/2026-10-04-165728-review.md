## High-level view

The busy gate is now resolved honestly: `triggerCareFx` returns early under the identical condition that makes `runCareAction` no-op, so the overlay and bounce never play for an action that didn't run. The one nuance is that `App.tsx` reads the `busy`/`monster` state values while `useMonster` consults a ref, so in principle they can be one render apart — but the buttons are disabled while busy, so a click can't land in that window.

The sleep/wake mismatch is fixed by modeling `wake` as a first-class care action with its own ⏰ cue and keyframe, selected off the same `isSleeping` flag that drives the underlying toggle logic. The two signals share one source of truth, so they can't diverge.

The sprite reaction now re-fires on every action: wrapping the sprite in a `.sprite-bounce-layer` keyed on the FX counter forces a remount per click, restarting the bounce animation where the old persistent class would not. `.sprite-wrap` keeps `position: relative`, so the absolutely-positioned overlays (💤/💢/`care-fx`) still anchor correctly, and the reduced-motion override moved to the new selector in lockstep.

Test coverage for the pure descriptor expanded to cover `wake` — exact descriptor, inclusion in the distinctness and duration-bound checks, and an explicit sleep≠wake assertion. The React/CSS wiring remains untested, consistent with the package having no DOM harness.

<summary>Details</summary>

### Busy gate now mirrors the action

`triggerCareFx` returns early on `game.monster === null || game.busy` before setting any state or scheduling the timer, and `game.busy`/`game.monster` are in its dependency array. `runCareAction` guards on `monsterRef.current === null || busy`. The conditions are semantically the same, so a click the action drops no longer produces a cue. The only gap is the state-vs-ref read: `App.tsx` sees the `busy` state value, `useMonster` the latest ref/state inside the callback. Because the care buttons carry `disabled={busy}`, a user click cannot arrive during the sub-render window where the two could disagree, so this stays theoretical (possible — would require a programmatic trigger bypassing the disabled button to observe).

### Wake modeled as a distinct action

`CareAction` gained `"wake"` and `CARE_EFFECTS` maps it to `{ className: "fx-wake", emoji: "⏰", durationMs: 600 }`, with a matching `.care-fx.fx-wake` rule and `fx-wake` keyframe (a pop-and-shake rotate, visually unlike the 💤 float-up). `handleSleep` selects `game.monster?.isSleeping ? "wake" : "sleep"`, and `useMonster.sleep` branches on the same `m.isSleeping` to call `wakeLogic`/`sleepLogic`. One flag drives both the logic and the cue, so pressing 起こす now shows ⏰ and pressing 睡眠 shows 💤.

### Sprite bounce re-fires via keyed remount

The sprite is wrapped in `<div key={careFx?.key ?? "idle"} className="sprite-bounce-layer ...">`. The incrementing key remounts the div on every action, so the `sprite-bounce 0.4s` animation (now on `.sprite-bounce-layer.reacting`) restarts even on a rapid second click of the same button — the exact repeat case the old `.sprite-wrap.reacting` class failed. `.sprite-wrap` retains `position: relative`, so the overlay emoji and the sleeping/dirty badges still position against it; the new layer only adds a `display: grid; place-items: center` centering context and does not establish a containing block for the absolute children. The `prefers-reduced-motion` override was moved to `.sprite-bounce-layer.reacting` to match.
