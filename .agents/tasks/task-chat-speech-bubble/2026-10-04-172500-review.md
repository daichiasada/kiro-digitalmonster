# Speech bubble for the latest monster reply near the sprite (v1)

The monster's most recent spoken line now renders as a speech bubble anchored above the sprite, inside the relatively-positioned `.sprite-wrap` alongside the existing 💤/💢 and care-fx overlays. A pure helper `latestMonsterReply(chatLog)` picks the last `monster` line (or null), a presentational `SpeechBubble` component maps `{text, pending}` to the typing cue / reply text / nothing, and App.tsx branches on `canChat(stageId)` so the baby stage surfaces the canned non-verbal line `BABY_SPEECH_TEXT` without ever hitting the backend. The right-hand `ChatPanel` transcript and input are untouched, no runtime deps were added, and all strings stay Japanese.

Watch for: the baby bubble is permanent and non-dismissable, so it overlaps the 💤/💢 sleep/dirty overlays and sits on screen for the entire baby stage (confirmed); `aria-live="polite"` re-announces the typing `…` and then the reply as two separate updates per exchange (likely); long replies are silently clamped at `max-height: 6em` with `overflow: hidden` and no ellipsis (confirmed).

**Verdict**: APPROVED

## High-level view

The design keeps the derivation logic pure and testable: `latestMonsterReply` is a React/DOM-free reverse scan over a structural subset of the chat log, so the Node test runner can call it directly. The component is purely presentational and is remounted via a content-derived `key` so the CSS fade-in replays on each new reply — the same keyed-remount trick already used for care-fx.

The baby-stage requirement is met without touching `sendChat`/`useMonster` or enabling the disabled input: App.tsx computes bubble text as `canChat(stageId) ? latestMonsterReply(game.chatLog) : BABY_SPEECH_TEXT` and forces `pending=false` for baby. `BABY_SPEECH_TEXT` mirrors the backend canned reply in `chat.ts` exactly, with a comment naming that source — the one duplication risk is that the two literals can drift silently since nothing ties them together at build time.

The visual gaps are cosmetic rather than behavioral: the baby bubble is always present (no dismiss path, overlaps the sleep/dirty emoji badges), accessibility announces the pending placeholder as its own live-region update, and overflow truncates long text without any affordance. None block the feature.

1. **Baby bubble is permanent and overlaps overlays** — the baby bubble renders unconditionally for the whole baby stage and shares the top-center region with the 💤/💢 badges; consider gating it (e.g. only after an interaction) or offsetting z-order/position so it doesn't sit on top of the sleep/dirty indicators.
2. **Live region double-announces** — `aria-live="polite"` fires for both the `…` pending state and the subsequent reply, so screen readers hear the typing placeholder as a distinct announcement; consider marking the pending state `aria-hidden` or only announcing settled replies.
3. **Long replies truncated without affordance** — `.speech-bubble-text` clamps at `max-height: 6em; overflow: hidden` with no ellipsis or scroll, so long non-baby replies are silently cut off; acceptable given the full text remains in the transcript, but worth a line-clamp with ellipsis.
4. **Baby string duplicated across packages with no enforced tie** — `BABY_SPEECH_TEXT` copies the backend canned reply from `chat.ts` by hand; the frontend test only pins the copy to itself, so the two can drift silently. Consider a shared constant or a test that asserts against the backend value.

### Deriving the latest reply as a pure helper

`latestMonsterReply` scans the log from the end and returns the first `monster` line's text, or null. Typing it against `ReadonlyArray<{ role; text }>` rather than the hook's `ChatLine` keeps it import-free of React, which is why `game-ui.test.ts` can call it under `node --test` without a DOM. The tests cover the cases that matter — empty log, player-only, single monster line, interleaved (asserting the *last* monster line wins), and the baby canned string — and a separate test pins `BABY_SPEECH_TEXT` to the exact literal. These are meaningful: they assert the reverse-scan ordering and the exact-string contract, and would fail if the helper were reverted to a forward scan or the constant drifted.

### Baby stage without a backend round-trip

The one piece of shared state between frontend and backend is the canned baby line. The backend returns `…！（まだ言葉を話せないみたい。もっと育ててあげよう！）` with `modelId: 'none'` (chat.ts line 100), and `BABY_SPEECH_TEXT` reproduces that literal with a comment pointing at the source. Because nothing enforces equality across the package boundary, the two can drift independently — the frontend test only pins the frontend copy to itself, not to the backend value (possible drift, confirmed there is no cross-package assertion). Low severity since the string is stable, but the "source of truth" comment overstates the guarantee.

Baby `canChat` stays false, `sendChat` early-returns, and the `.chat-disabled-hint` in ChatPanel is untouched, so the disabled-input UX is preserved while the bubble independently shows the non-verbal cue with `pending=false`.

### Keyed remount and the fade-in

```
.sprite-wrap (position: relative)
├── sprite-bounce-layer (key=careFx)   ← MonsterSprite
├── SpeechBubble  → <div key={`${…}:${content}`}>   ← fade-in replays on key change
├── 💤 / 💢 (conditional)
└── care-fx (conditional)
```

The `key` lives on the `<div>` returned inside `SpeechBubble`, derived from `pending` plus `content`, so a new reply replays the `speech-bubble-in` keyframe — matching the care-fx pattern and satisfying the "fade-in on new reply" requirement. `pending` is checked before `text`, so a stale reply never shows under the typing indicator. The `prefers-reduced-motion` guard disables the animation.

### Positioning, overlap, and overflow

The bubble is `position: absolute; top: 10px; left: 50%` with a downward border-triangle tail at `bottom: -8px`, so it reads as coming from the sprite below, and `pointer-events: none` keeps it from blocking sprite interaction. Two cosmetic consequences for the always-on baby bubble: it occupies the same top-center zone as the 💤/💢 badges (which are positioned top-left/absolute elsewhere) and persists for the whole stage with no dismiss path, so a sleeping dirty baby shows the bubble plus both badges stacked. The `max-height: 6em; overflow: hidden` on `.speech-bubble-text` clamps long non-baby replies with no ellipsis — the full text still lives in the transcript, so this is a graceful-degradation choice rather than a bug, but the truncation is invisible to the user.

### Scope and tests

The diff is tightly scoped to the five intended files; no `package.json` changes, no runtime deps, no unrelated edits. Frontend tests go 27 → 33 (6 new), root stays 47/47, build green per the orchestrator.

Not tested: the `SpeechBubble` component's render branches (pending vs text vs null) and the App.tsx `canChat` gating are not unit-tested — only the pure helper and the constant are. That's consistent with the repo's React/DOM-free test posture (no component test harness exists), so it's a known gap rather than a regression.
