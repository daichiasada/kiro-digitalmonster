# Time-of-day and state-aware stage background (v1)

Issue #43 makes the stage visually reflect the device's local time and the monster's care state. A pure `timeOfDay` helper maps a local hour to one of four phases (morning/day/evening/night), App.tsx surfaces that phase plus the growth stage and sleeping/dirty state as attributes/classes on the existing `.stage-area` wrapper, and styles.css drives everything from CSS gradients and overlays: a per-phase background gradient, a per-stage radial hue tint, a stage-level sleeping dim, and an edges-only dirty vignette. A separate ~60s interval recomputes the phase and only re-renders when the phase string actually flips, keeping the 15s game-logic TIME_TICK untouched.

Watch for: nothing blocking. The sleeping `brightness(0.78)` filter is applied to the whole `.stage-area` column, so the ChatPanel and speech bubble dim along with the backdrop while sleeping (confirmed, intended cue, contrast still passes). The numeric-input branch of `timeOfDay` treats 0-23 as a bare hour and anything else as a timestamp, which is correct for the only production caller but has a theoretical edge for sub-24 timestamps (possible, not reachable here).

**Verdict**: APPROVED

## High-level view

The phase logic lives in a pure, React/DOM-free `timeOfDay(input: number | Date)` next to `dayStamp`, so it is unit-testable under the Node runner. Ranges are morning 5-9, day 10-16, evening 17-19, night 20-4 (wrapping midnight), with non-finite input falling back to `day`. The three added test blocks assert every boundary hour, Date inputs, and the fallback, and would fail if any range edge were off by one.

App seeds `tod` from the current local hour and refreshes it on a 60s interval that uses a functional update returning the previous value unless the phase changed, so there is no repaint per tick, and the interval is cleared on unmount. The attributes/classes land on the pre-existing `.stage-area` div rather than a new wrapper, so the sprite's own sleeping dim, the 💤/💢/🍖 badges, the care-fx overlay, and the speech bubble are untouched and layer on top.

Contrast holds on every phase. All gradient stops stay in the dark `--bg` family, and the lightest stop anywhere (morning `#2a3a66`) still gives `--text #eef3ff` a 9.97:1 ratio and `--muted #a9b6d6` 5.46:1, both well above AA's 4.5:1. The speech bubble additionally sits on its own `--panel-2` panel. The only motion is a one-shot `transition: background 0.6s ease` on the stage and its `::before`, nulled under a new `prefers-reduced-motion` block; there is no keyframe animation. Perf is gradient/opacity/filter only. No runtime deps, no i18n changes (none were needed), build clean, shared 152, frontend 123.

### Phase classification and its tests

The branch order (`<10`, `<17`, `<20`, else `night`) makes `night` the catch-all that absorbs both the 20-23 and 0-4 halves of the midnight wrap without special-casing. An invalid Date cannot leak through because the derived hour is re-checked for finiteness after conversion.

The boundary tests pin each edge hour (4→night, 5→morning, 9→morning, 10→day, 16→day, 17→evening, 19→evening, 20→night, 23→night, 0→night), so an off-by-one in any comparison would fail at least one assertion rather than pass silently.

The numeric overload disambiguates bare hour from timestamp by range (`input >= 0 && input <= 23`), which is right for the production path (App always passes `new Date()`) and the tests (bare hours). The theoretical gap is a genuine epoch-adjacent timestamp (0-23ms) being read as an hour, which no caller produces.

### Stage wiring and repaint avoidance

```
useMonster 15s TIME_TICK ──► game logic (untouched)
App 60s interval ──► timeOfDay(new Date())
                       └─ setTod(prev => prev === next ? prev : next)  // re-render only on flip
.stage-area[data-timeofday][data-stage].is-sleeping.is-dirty
   ├─ ::before  per-stage radial tint   (z-index 0)
   ├─ ::after   dirty vignette          (z-index 0)
   └─ > *       sprite / bubble / panel (z-index 1)
```

The background interval is deliberately separate from the game-logic tick and only commits state on an actual phase change, so a session left open crosses a boundary (09:59→10:00) without repainting on every tick. `data-stage` reads the live `game.monster.stageId`, whose values (`baby`/`rookie`/`champion`/`ultimate`) match the CSS `[data-stage=...]` selectors one-for-one, so the per-stage tint always resolves. Content is lifted to `z-index: 1` above the `::before`/`::after` overlays, both of which are `pointer-events: none`, so the pet target is never blocked.

### Contrast and reduced motion

Every phase keeps both gradient stops in the dark navy family. Measured ratios against `#eef3ff` body text: morning 9.97 (lightest stop) / 14.28, day 11.21, evening 12.76 / 15.48, night 14.97. Muted `#a9b6d6` stays at or above 5.46 on the lightest stop. The sleeping `brightness(0.78)` scales foreground and background together, so it does not erode these margins, and the speech bubble is insulated on `--panel-2` (11.21 for text) regardless of the gradient behind it.

The only animation introduced is a one-shot `transition: background 0.6s ease` on `.stage-area` and its `::before`. The new `@media (prefers-reduced-motion: reduce)` block sets `transition: none` on both while leaving the correct static gradient and overlays applied, consistent with the existing reduced-motion blocks in the file. No continuous keyframe animation exists on the stage, so nothing else needs stilling.

### Perf and scope

Visuals are CSS linear/radial gradients plus `opacity`/`filter` only, with no large images, no box-shadow spam, and no running keyframes, so the composite changes at most four times a day; the JS cost is one 60s timer re-rendering only on a flip. Build compiles clean under TS strict; shared tests stay at 152 and frontend rises to 123 (120 + 3). No runtime dependencies were added, and i18n.ts is unchanged (the sleeping/dirty badges already carry `badge.sleeping`/`badge.dirty` aria labels, so a purely visual change needed no new strings).
